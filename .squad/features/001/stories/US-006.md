**Resumo:** Gerenciar múltiplas configurações de ambiente (Desenvolvimento, Homologação, Produção)

### Caso de Uso

- **Como um** desenvolvedor que testa publicações contra mais de um ambiente corporativo
- **Eu quero** cadastrar e manter várias configurações de Kafka e Schema Registry
- **para que** eu alterne entre ambientes sem perder ou misturar dados de configuração

### Critérios de Aceite

**Cenário 1: Criar múltiplas configurações**
- **Dado** nenhuma configuração cadastrada
- **Quando** o desenvolvedor cria três configurações com nomes distintos
- **Então** todas ficam disponíveis para seleção nas telas de publicação e de teste de conexão

**Cenário 2: Editar uma configuração sem afetar as demais**
- **Dado** múltiplas configurações cadastradas
- **Quando** o desenvolvedor edita os dados de uma delas
- **Então** as demais configurações permanecem inalteradas

**Cenário 3: Publicar usando uma configuração específica**
- **Dado** múltiplas configurações cadastradas
- **Quando** o desenvolvedor seleciona uma configuração específica para publicar uma mensagem
- **Então** a publicação usa exatamente os dados de Kafka e de Schema Registry daquela configuração

**Cenário 4: Nomes de configuração duplicados**
- **Dado** duas tentativas de configuração de ambiente com o mesmo nome
- **Quando** o desenvolvedor tenta salvar a segunda configuração
- **Então** a ferramenta impede a duplicidade de nomes ou deixa claro qual configuração está sendo usada
